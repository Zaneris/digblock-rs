# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Rust + wgpu rewrite of the DigBlock voxel engine (originally Java/libGDX, 2015–2017). The faithful-port goal is complete; the engine is free to diverge and improve. The old Java repo at `../DigBlock` is a behavior reference, not a constraint.

**Where the detail lives.** This file is orientation plus the invariants that bite if broken. The reasoning, the measurements, and the alternatives that were tried and declined live in the design docs — read the relevant one before re-litigating a decision or rebuilding something:

- `GI-DESIGN.md` — lighting: data model, pass order, tuned constants, release notes R8–R25, and an honest "What is NOT built" list.
- `BENCH.md` — every perf measurement, including the ones that refuted a hypothesis.
- `SKILLS-DESIGN.md` — skills, XP curve, essences, transmutation catalog, milestones.
- `NET-AUDIT.md` / `NET-AUDIT-2.md`, `PERF-AUDIT.md` — netcode and frame-pacing audits.

## Commands

```sh
just run                  # run desktop app (cargo run -p digblock-desktop)
just run --drill          # automated lifecycle drill (suspend/resume + device-loss)
just bench                # deterministic perf run: release, scripted flight, CSV + summary;
                          # --no-vsync for uncapped raw-cost percentiles; findings in BENCH.md
just check                # full gate: fmt --check, clippy -D warnings, cargo test --workspace
                          # (needs Docker: server e2e tests boot the apps/master container)
just check-ios            # cargo check for aarch64-apple-ios (no Xcode needed)
just web                  # wasm build + serve at http://localhost:8080 (Chrome/WebGPU; needs
                          # wasm-bindgen-cli at Cargo.lock's exact version)
just web-live             # same, but probes the production master first and defaults the URL
                          # to ?overlay&spikelog (frame-pacing diagnostics)
just check-web            # clippy for wasm32-unknown-unknown — no CLI tools needed
just play                 # master container + native server + client at the menu
just play-web             # same but serving the web bundle; open the printed URL
just play-docker wifi     # desktop client vs containerized stack (clean | wifi | cellular netem)
just ios-sim / ios-device # build+run via Xcode (full Xcode required)
just master               # .NET master natively (QUIC probe needs `brew install libmsquic`)
just server               # dedicated server (journal in ./data; --master-url defaults to the
                          # production master https://master.digblock.net; joining is token-only)
just bot -- --bots 4      # headless bots: pick a server via the master, mint tokens, join
just compose wifi         # dockerized master + server behind tc netem
just compose-bots wifi    # same + 4-bot soak, exits non-zero on missed snapshots
just profile              # release-speed build with debug symbols
```

Run a single test: `cargo test -p digblock-core --test worldgen` or `cargo test -p digblock-core <test_name>`. CI is intentionally disabled pre-deployment (`.github/workflows/ci.yml.disabled`); `just check` + `just check-ios` are the gate.

Formatting uses hard tabs, max width 100 (`rustfmt.toml`).

Base images/toolchains in CI and Docker files are **suite-pinned on purpose** (builder and runtime must share a glibc; floating `1-slim` once broke a release). Bump the pins in `docker/Dockerfile*`, `.github/workflows/*`, and `apps/master/Dockerfile` deliberately — together where the comments say so — with a test release.

### Networking & dev gotchas

Multiplayer is master-first with **no direct-connect path**: the .NET master (`apps/master`) lists servers, distributes cert pins, and mints one-time join tokens; a game server refuses any Hello it can't verify with the master. Display names are mandatory (3–10 chars of `a-z A-Z 0-9 - _`; canonical `validate_name` in `digblock-net/src/protocol.rs`, mirrored as a regex backstop in the master's `/api/join` — which is why names stay ASCII-only). Chat: T/Enter to type; the server sanitizes to the Latin free-text alphabet (`is_text_char`/`text_charset`, printable ASCII plus Latin-1 and Latin Extended-A so European players can type their own words) and rate-limits (`CHAT_*`). Admin: `--admin-name`/`DIGBLOCK_ADMIN_NAME` grants chat commands (`/help /tp /goto /bring /time /ban /ban-list /unban /set-spawn /set-spawn-dir /lock-spawn`) — bans by IP in `data/bans.json`, spawn overrides in `data/spawn.json`, table and handlers in `apps/server/src/sim/admin.rs`, advertised to the client for Tab-autocomplete via `ServerMsg::AdminCommands`. `just play`/`just play-web` default the admin to name `admin`. Compass in `/tp`: east = sunrise = −x, north = −z.

Dev gotchas: use `127.0.0.1`, never `localhost` (macOS resolves it to `::1`; the server binds IPv4 only). The containerized master probes the host via `probeHost = host.docker.internal` — a LAN-IP hairpin breaks QUIC address validation under Docker's NAT, and production servers omit `probeHost`. If a client times out against the docker stack, read the server container's logs before blaming the network: a server dead at boot looks identical. Extra windows: `just run -- --master-url http://127.0.0.1:5200`, add `--join --name <name>` for scripted flows.

### Capture, bench & metrics flags

For `just run`:

- **Scene/pose**: `--seed <f64>`, `--pos x y z` (the scenes this engine is slow in are NATURAL water, terraced and cascading — no synthetic plan builds those), `--tod <deg>` freezes the sun (dev builds, or release **with `--exit`** — a run that ends itself is a capture, not a session), `--draw-dist N`, `--mobile` (the iOS config), `--workers N`.
- **Determinism**: `--fixed-dt S` steps the world by exactly S per frame. Required for any A/B — everything animated rides dt, so without it two builds of different speed reach `--frames N` in different world states and the diff measures the speed difference.
- **Output**: `--screenshot out.png`, `--frames N`, `--exit`, `--metrics-csv`, `--overlay` (backquote toggles), `--no-vsync`.
- **Motion**: `--fly N` vs `--warp N` — fly the bench path N frames then freeze, vs land on that same pose with no motion behind it. That pair is the only way to photograph a TEMPORAL artifact; every other capture is a still, which is exactly when a temporal artifact has already converged away. `--walk` swaps the flyover for an eye-height oscillation one block forward and back: a screen-space artifact scales with SCREEN motion, so flyover and walk are two regimes and the walk is the one players report from. `--bench-speed B` sets the flyover's blocks/s (default **30** — every BENCH.md baseline was taken there, do not change the default); 30 is a different STREAMING regime, not merely a faster one, because the GI upload budget can't keep up and the classify drain drops entries, so a cost that only appears there may be budget starvation rather than a leak. `--bench-speed 4` soaks at how the game is actually played; `--walk` is not a substitute, since its one-block oscillation never brings new terrain into the window. Repeat noise on both paths is ≤0.008, so a difference of 0.1 is signal (GI-DESIGN.md "Measuring motion"). For FLICKER specifically, diff frames N and **N+90** on a `--walk --fixed-dt 0.0166667` run: the oscillation's 1.5 s period is exactly 90 frames, so the two sit at the identical pose after continuous motion and the diff holds no parallax — frame N vs N+1 is mostly parallax and cannot separate the two (R27). Always pair `--fly` with `--bench`: `--fly` alone silently takes the interactive path — menu up, the user's SAVED settings loaded, audio on, master dialed — and is not hermetic.
- **Attribution**: `DIG_STUB=<terms>` (`renderer::stub`) removes one shading term per run so ONE build attributes a frame — water `wvert wsun wssr wripple wrefract wflat spray nowater`, GI `gisun gigather ginee giflat giatrous`, raster `noscene noraster`. Uniform-branch gated, so an un-stubbed run pays nothing, and a typo is fatal rather than silently measuring the un-stubbed build. `noscene` is the CLEAN raster stub (the prepass still runs, so depth, face codes and GI are untouched); `noraster` drops the prepass too and is an UPPER BOUND only, because an empty depth buffer sends every resolve pixel down the sky early-out. Never subtract the two to "get" the prepass.
- **Scenes for capture**: `DIG_VAULT` (sealed stone vault + torch — NEE, and any look call about a dim room), `DIG_ROOF` (wall-less plate overhead; pins that the beam knows the sun's angle rather than a sky column), `DIG_DIVE`, `DIG_SHAPES`, `DIG_RIVER` (flooded basin ahead of spawn + `--pitch -35`, the only pose with a SHADED water surface on screen), `DIG_PLAYERBOX=1` (fake remote player for GPU-path checks), `DIG_TORCHES=<n>` (an open courtyard lit by n torches, cluster 17 blocks out and floor running past `LIGHT_RANGE` — the local-light capture DIG_VAULT cannot be, since an eleven-block room has no far band and one torch is the single count the NEE covers completely; `DIG_TORCHES_FAR=<n>` parks emitters where they change only the light list's LENGTH, `DIG_TORCHES_WALL=1` screens the cluster so emitters occlude each other), `DIG_CONFETTI=1` (a level-up burst every couple of seconds ahead of the camera — the event is rare and transient, so it is otherwise invisible to capture), `DIG_SCREEN=menu|inventory|alchemy|transmute|skills|hand|bucket|bucket-full` (opens that page at startup, stocking the inventory — the pages are otherwise input-only and invisible to headless capture, which is how two look-and-feel regressions shipped; `hand` just stocks the bar so the viewmodel is visible, `bucket`/`bucket-full` select the water tool empty or charged).
- **Capture gotchas**: `--size` sets logical size but the physical framebuffer follows the display's backing scale — verify capture pixel dimensions before comparing frame-time runs. On a multi-monitor desk the window opens wherever the desktop last had focus, so **`--display N` (R27) is mandatory for any frame-time bracket**: refresh rate rides the screen, and a display-paced frame lets the GPU downclock, which inflates every timestamp in the CSV — an unpinned before/after bracket measures the screens (`refresh_ms` of 16.67 vs 8.33 in the CSV is the tell). The chosen monitor's name, size, scale and refresh are logged, and an out-of-range index is fatal. Physics ticks ride the wall clock, so cross-build stills need ≥1200 frames for both cameras to be long at rest, or the whole diff is a sub-block pose shift.

Metrics (`digblock-core/src/metrics.rs`) land in the 5s log line, the CSV, and the overlay; `DIG_SPIKELOG=1` logs per-phase breakdowns of over-budget frames. **F7** (or `--gi-drill-at N` headlessly) clears the GI's derived state and re-queues every resident chunk. The overlay's `sky`/`emit` fields climb over a session and never come down — but that ratchet is **not** a leak: the A/B (BENCH.md 2026-08-12) shows frame time unmoved across a clear, so a session's rising ceiling is real terrain entering the window. Don't re-litigate it. Note `gpu_gi_denoise_ms` now sums BOTH à-trous iterations; pre-2026-08-12 CSVs report the stride-2 pass alone and read roughly half. Streaming work is time-budgeted per frame (`STREAM_BUDGET_MS`) and the wide shadow cascade re-renders sliced across frames, so streaming can't hitch the render loop.

## UI theme

`digblock-render/src/ui/theme.rs` owns every spacing token and color the screens share (`PAD`, `ROW_H`/`ACTION_ROW_H`, `ROW_GAP`, `SECTION_GAP`, `GAP_ABOVE_BAR`, `MIN_PANEL_W`, plus `PANEL_BG`, `SCREEN_DIM`, `FILL_BG`) — menu, inventory and alchemy all read from it, and a constant only one screen uses does not belong there. Three load-bearing rules:

1. **Every token is a logical size**, multiplied by `Style::scale` exactly once at the point of use.
2. **A frame has exactly one text size**, `Style::glyph` (= `scale::glyph_px`), with `scale::FIXED_GLYPH_PX` (hotbar counts, debug panel) the only sanctioned exception.
3. **A screen is one panel color over one dim**, menu included.

The last two are pinned by `screens::every_screen_draws_text_at_one_size` (three window sizes × four scales) and `every_screen_dims_and_panels_the_same_way`, because both have regressed visibly before — the menu and in-game screens once carried different panel/dim pairs, and the alchemy screen shipped with a 1.35× title and a shrink-to-fit that scaled its glyph by an arbitrary fraction.

A panel too tall for its window shrinks through `theme::fit_scale`, which steps the WHOLE style down in quarter increments, re-measuring per rung (`glyph_px` rounds) — never a fractional glyph. `ui_scale` quantizes **only** its derived half (display density × window size, which shimmers unquantized under a window drag); the user's preference multiplies in exactly, which is what makes a 5% slider notch mean something. So the effective scale is NOT on a quarter grid — don't write a test that assumes it is.

## Skills & XP

Two skills (Mining, Alchemy), levels 1–99, designed in `SKILLS-DESIGN.md` (M1–M4 + consolidation are built; M5+ are still design). Everything shared lives in `digblock-core/src/skills.rs`:

- The `Skill` enum is `repr(u8)` and **append-only** — the index is a wire/persistence format.
- The XP curve is a **pinned integer table**, never `powf` — a golden constant both sides must agree on (`xp_curve_table_is_pinned`).
- Award tables (`dig_xp` = ceil(hardness/6), `alchemy_xp`) and dig speed (SIM v12): `dig_required(block, hardness, level)` keys on the block's `DigFamily` (a `blocks!` `dig`-builder field — Fixed/Soft/Wood/Rock, every family EXACTLY 1000‰ at level 30, the legacy table as shared golden). The harness's `dig_hold` stretches holds by the actual family curve — never assume ×1.25.
- Storage is XP-only `u64` totals; level is always derived.

**Every level threshold in the game lives in `digblock-core/src/unlock.rs`** — nothing else may hold an unlock number, and no caller compares levels itself. Four tables (`craft`, `extract`, `mine`, `pickup`) and the questions asked of them (`can_craft`, `can_extract`, `dig_blocked`). Two dig gates, one pattern: `mine` is §5.1's rock gate (Mining 3–5 for rock, `RejectReason::SkillGated`, protocol v17) and `pickup` (SIM v13) refuses a **craft-only** block — `crafted` in its `blocks!` row, meaning worldgen places none, pinned by `worldgen_never_places_a_crafted_block` — below its own `unlock::craft` level, so a pickup can't route around an unlock (`RejectReason::NotUnlocked`, protocol v19). `pickup` keys on the DROP (pristine Stone hands out Rubble, so quarrying stays a Mining question) and on craft-*only*, never craftability — `Wood` has a level-20 recipe and grows on trees. Client prediction, the server's DigStart backstop, the bot's filter and the harness all call `dig_blocked`, which returns the first unmet `Requirement` (Mining before Alchemy) carrying `Kind::message()` — the ONE wording each refusal speaks, which is why the wire sends a reason and never a sentence. `unlock::opens(skill, level)` derives what a level hands you from those same tables; the level-up fanfare and the character screen's teasers both key on it (`every_unlock_level_has_prose`).

**XP is server-computed at exactly two chokepoints** — the dig-credit block in `sim/edits.rs` and `process_alchemy` — and reaches the client as `ServerMsg::XpGain` carrying the new **TOTAL** (idempotent, reorder-safe; the client takes the max and animates the delta). Join sync always sends `ServerMsg::Skills`, even empty, right after `Layout`. Offline play awards through the same core functions in the engine's offline arms only (`complete_dig`'s `_ =>`, `apply_alchemy_action`'s `_ =>`) — never award in the shared prediction path, or multiplayer double-pays.

Persistence: `inventories.bin` v4 appends a skills blob (v1–v3 read-compat — a routine upgrade must never trip the archive path); local saves carry `skills` in `state.json`/`WorldSave` with serde defaults. UI: the character screen (`ui/screens/character.rs`, C key + pause-menu row + `DIG_SCREEN=skills`, member of both pinned theme tests), coalescing `+N SKILL` toasts above the hotbar (`hud::xp_toasts`), and a level-up feed line + sfx via `Engine::apply_xp_total` — both award paths land there so presentation can't drift.

## Lighting (RTGI)

Lighting is probe-traced GI and it is the **only** render path — no flag. The raster stack it replaced is deleted (shadow.rs/shadow.wgsl, light.rs and the Stage-B nibble field, baked AO, all fog, LIGHT-DESIGN.md); with AO gone the mesher's quad winding is fixed rather than AO-keyed, and the vertex words are repacked (w0: pos 0–23, normal 24–26, corner 27–28; w1: layer 0–9, uv 10–17, emissive 18).

**`GI-DESIGN.md` is the reference** — data model, pass order, every tuned constant, R8–R27 release notes with their measurements, and a "What is NOT built" section. Read it before changing lighting. Several plausible ideas in there were built, measured and **declined**, with the numbers recorded so they don't get rebuilt: a 64-cube super-brick skip mip, a per-column heightfield sun-march skip (parked at tag `archive/r19-column-skip`), and widening the voxel window to the streamed radius.

The shape, in brief: a GPU voxel window plus an 8-block coarse texture feed two toroidal ambient-cube probe cascades (compute, swept in a **permuted** round-robin so convergence isn't a visible band, one NEE sample per ray, rays terminating in last frame's field for multi-bounce). Probes are a **cache**, not the final signal. A half-res resolve fires two per-pixel rays: a cosine-weighted **final gather** marched through the window and terminated in the probe cache at the hit (one ray buys the whole multi-bounce series plus contact darkening), and one **deterministic** sun ray along the exact unquantized caster, its 0.5° cone offset static and hashed from eighth-block WORLD cells, so a point asks the same question from every camera. `gi_sun_vis` returns the occluder distance and the penumbra is reconstructed spatially from it. The result accumulates temporally by reprojecting through `prev_view_proj` — exact for static geometry, so no motion vectors — and is filtered by `gi_atrous.wgsl`, two edge-stopping à-trous iterations stopping hard on face code and view distance and softly on each signal's own **analytic** variance. Solids bilaterally upsample it against exact face normals rasterized by the depth prepass into R8Uint; water gathers its indirect **per vertex** (R17 — the prepass runs a position-only `vs_depth` sharing the color vs's `water_world` decode so the `@invariant`/LessEqual contract holds) and gates its two ray marches on their own contribution (R21). Reveals prime from the probe cache rather than restarting at n = 1 (R15), and the resolve's per-pixel NEE **resamples every in-range emitter** through a one-pass weighted reservoir (R27; R20 built the ray and picked the argmax) — which is what lights the block a torch stands on. Direct light has exactly ONE estimator: the gather returns no emitter radiance at all.

Invariants that bite if broken:

- **The accumulator must be rgba32f** (`gi::GI_ACC_FORMAT`). A 10-bit mantissa makes a 1/512 update round to zero, so every pixel freezes where it stood; `history_format_resolves_the_accumulator` pins N_MAX against the format.
- **The two lighting pairs have FIXED roles, not ping-pong**: `[0] ←resolve→ atrous(1) → [1] → atrous(2) → [0] →scene`. That leaves the once-filtered image parked in `[1]` as next frame's history, which is exactly what SVGF feeds back.
- **History length `n` rides the sun target's g channel** as `code + 256·n` (exact in f32, pinned by `packed_metadata_stays_exact`) because WebGPU's 32-byte attachment budget is spent. Every reader masks `& 255u`.
- **The history fetch is bilinear, per-tap validated on face code and view distance, and `n` is two-state** — snapped onto the lattice (full history) or `N_MOVING`. Travel is not zero at rest: the f32 round trip drifts 0.055–0.11 texels with the camera dead still, and resampling that every frame is what streaks resting surfaces. `a_moving_pixel_always_gets_the_spatial_filter` pins `N_MOVING < N_CONVERGED`.
- **No moments buffer.** Both estimators have an analytic variance from data already stored (sun visibility is a mean of n Bernoulli trials, so its standard error is exactly `sqrt(p(1−p)/n)`), which saves a whole ping-ponged rgba32f and a pass of bandwidth — and cannot drift out of step with the accumulator.
- **Sun thresholds are in RADIANCE** (`SUN_MIN_L`, weight × `light_color`), never a bare blend weight. There is no tonemap, so a 2% weight against an HDR sky is a 10% error.
- **Twilight strength (`light_dir.w`) multiplies the LIGHT, never the shadow.** `mix(vec3f(1.0), visibility, light_dir.w)` is the shadow-map-era form; against a traced visibility it returns 1.0 as strength falls, lighting every caster-facing surface at twilight through walls.
- **Water writes OPAQUE** (R25). The fragment samples `scene_tex` and runs the whole transport across `thick`, so `back + surf` already IS the backdrop — alpha-blending it over the same backdrop re-adds an unabsorbed copy. Alpha is the falling-sheet streak gate alone (`0.75 + 0.5·s`, exactly 1.0 on every still surface).
- **`gi_dda.wgsl` is the one DDA** and is dependency-free so the compute kernels can share it. It owns the two-level brick skip, the sky ceiling test (R18 — a non-descending ray above the window's highest occupied cell is a proven miss in one compare), `gi_lateral_max`, and `gi_boxes_hit` (R16: shaped cells classify into synthetic PARTIAL classes and every march clips the ray's in-cell span against their boxes, so a slab shadows as a slab and an open door lets light through). Every partial cell blocks only where its boxes stand, emitters included — R27 retired the emitting-whole-cell rule along with the direct-hit term that was its only reason to exist, so a torch no longer casts a full-cube shadow from a 2/12 post. Every march steps BEFORE it tests, since a shaped block's surface lies inside its own opaque cell.
- **`medium_common.wgsl` is the one participating medium**: `col·exp(−σd) + L_in·(1−exp(−σd))` with L_in = `sky_base`, the same function the sky pass draws, so terrain fades into exactly the sky pixel behind it and the streaming rim disappears. Air σ is a Koschmieder visibility distance, water σ is measured beam attenuation, and it is the ONLY water extinction — `gi_sun_vis` returns a water PATH LENGTH so the sun ray and the view ray cannot disagree. There is no fog, no INDIRECT_K, no tonemap.
- **Per-block tint (`block_tint` in chunk.wgsl) multiplies albedo, never light** (R23). The à-trous filter and the 512-frame accumulator only ever see the lighting buffers, so a per-block step in the light is a signal they are built to smooth away; on albedo it lands after the bilateral upsample where nothing can filter it. Derived from the world position and face code `fs` already carries — no vertex bit, no re-mesh, no new varying — and structurally excluded from emissive ink.

Light stays two independent block properties: `emissive` (the `glows` builder — fullbright ink, bit 18 of solid word 1, chunk.wgsl's early return) and `light` (the `emits(level)` builder — the cast level, feeding the GI material LUT and the light list in `gi.rs`, nothing else). The Torch (`ShapeKind::Torch`, stateless, baked in shapes.rs) glows AND emits 14; it is hand-priced in `alchemy::craft_ideal` (4 Flora + 2 Earth, Alch 8) because functional items are priced by hand, NEVER by the volume rule (`craft_costs_derive_from_collision_volume` deliberately excludes them). Torch shadows are hard point-light shadows by design, cast from `gi::light_origin(class)` — the cell centre for anything unshaped, and for a shaped emitter the centre of its emissive band (a torch radiates from its flame at 8.5/12, not from its handle; R26). `LIGHT_RANGE`/`LIGHT_GAIN`/`LIGHT_NEAR` are pinned across both shaders by `resolve_and_probe_agree_on_light_calibration`; `LIGHT_NEAR` = 2.0 is where the point model's near field stops being taken literally (R22), and chunk.wgsl's emissive INK gain by luminance (`1 + 1.6·lum²`) keeps a source out-reading what it casts — barely, since that ink is already clamped by the scene target and cannot be raised to follow a brighter pool, which is what caps `LIGHT_GAIN` at 0.75. NEE's stop-short margin is NOT a constant: `gi_light_margin` (gi_dda.wgsl, shared so both passes agree by construction) is the light's distance to the farthest corner of its own cell, because a fixed 0.9 only covers that cell while the origin is its centre. Both are stopgaps for the missing tonemap — which cannot simply be appended, because the offscreen scene colour uses the SURFACE format, so radiance is already clamped at the scene pass. `flush_lights` re-sorts on >16-block camera movement when emitters exceed MAX_LIGHTS; spray and viewmodel read a camera-light buffer.

## Alchemy & the economy

The economy lives in `digblock-core/src/alchemy.rs` — extraction yields (level-scaled 40%→100%), bonus lines, waste multipliers (1.60×→1.05×), craft unlocks, extraction pace — all integer math, and `apply_alchemy(inv, op, level)` is level-aware. Four load-bearing rules:

1. **The Rubble rule** — Stone/Sandstone `drops: Some(Rubble)`. Clean rock is craft-only, which is what makes transmutation the economy.
2. **No matter creation** (`no_level_ever_creates_matter`): craft cost strictly exceeds extraction yield in every essence at every level.
3. **Bonus lines only on recipe-less blocks** (`bonus_lines_never_sit_on_craftable_blocks`) — a bonus on a craftable block is an essence pump.
4. **The essence indices ARE the migration** — `Essence { Flora=0, Earth=1, … }` keeps the retired Material enum's numbering so legacy sub-material pairs decode 1:1. Never renumber.

The alchemy screen (K) is two tabs. **EXTRACT**: the real inventory grid plus one extraction slot — a *pointer* to a block id, never a container; drag a stack on and it drips one client-paced `Convert{count:1}` per `extract_pace_ticks(block, level)` (`AlchScreen::tick`, driven from `Engine::update`) — the pace is the block's `convert_xp` against the 9-XP whole block, so the bench spends time in proportion to what comes out, floored so 1-XP foliage isn't a wire-op stream. The server's bucket therefore banks **ticks** (one per tick, capped at `extract_burst_ticks(level)`) and a Convert spends the requested block's own pace. **TRANSMUTE**: family tiles whose icons rotate through their members on the screen's clock (the outgoing member shrinks and fades away and the incoming one grows in — `family_preview`; never a cross-fade, which double-exposes two 3D icons' internal faces, and never the hard cut it replaced); selecting a family lays out member tiles (locked ones dim but selectable, affordable ones badged) under a detail strip and the tab's ONE `TRANSMUTE` button — CLICK 1 · SHIFT 10 · CTRL 100. A §7.2 material × shape pair is one more member in an existing family, so the catalog grows without the screen growing (`every_craftable_appears_in_exactly_one_family` pins the mirror; tile rows wrap through `GridSpec` at 9 columns).

Polish invariants: everything sits on ONE left column; panel height is the max of both tabs, bottom-anchored (`panel_height_is_the_same_on_both_tabs` — a per-tab height jumped the top edge); the active tab's fill fuses into the content and the strip's rule breaks beneath it; `widgets::slot` carries hover plus a two-weight ring (`SlotRing::Weak` = selected family context, `Strong` = the acted-on member); locked tiles dim with an unlock badge while unaffordable ones stay full-color and the detail strip names the shortfall; a rejected drop explains itself on the preview line for ~2s.

Wire facts: sub-materials ride every wire/save format as flagged ids (`0x8000|essence`, 1 block = 27 units); shaped-item costs come from `alchemy::craft_ideal` (volume-derived via `craft_recipe`, hand-priced for functional items) with the level's waste multiplier on top. `ClientMsg::Alchemy` is NOT client-predicted — the server answers every op with an `InventoryFull` rebase — and rides the edit action queue so craft-then-place in one tick debits in wire order; offline runs the same `apply_alchemy`. The server enforces the drip via a per-player extraction token bucket in `process_alchemy`, banked in ticks and charged the block's own pace × count so neither a bulk `Convert{count:999}` nor a stream of cheap blocks can sidestep it; refusals answer with the standing rebase (nothing debited, no XP). That gate lives in op validation, NOT `apply_alchemy`, so the offline economy is identical and unpaced.

While ANY UI surface is open the engine synthesizes cursor + left-button from the primary touch at the top of `Engine::input` — one site gives iOS every screen, and no screen knows about touch.

## Settings & local worlds

The in-game Settings screen exposes draw distance (runtime-applied; connected clients send `ClientMsg::SetDrawDist` so the server's sync radius follows), **Render Scale** and **Lighting Detail**, an interface-scale multiplier (`--ui-scale`/`?uiscale=`; 70–150% in 5% steps, bounds owned by `ui::scale` and re-exported from `settings.rs` for the launchers; every one of the engine's five recompute sites routes through `recompute_ui_scale`), Music/SFX volumes, and an SSR toggle.

**The two resolution knobs** (`settings.rs`, `renderer::RenderScale`): the world renders into `scene_view`/`post_view` at `surface × render_scale` and ONE upscale pass takes it to the surface, after which the overlay draws at native — so UI, text, name tags and the crosshair are never resampled. (Name tags project `view_proj → NDC × size`; the `size` fed to the overlay must stay the SURFACE size, which is the one way this silently regresses.) GI runs at `render_size / gi_scale_div`, an INTEGER divisor (1/2/3/4, `--gi-scale`, "Ultra/High/Medium/Low"); the ratio rides `frame.misc.w`. GI scale is a fraction of the RENDER size, not the surface.

Which knob to spend is **measured, not intuited** (BENCH.md 2026-08-12): render 0.7 and gi 3 each buy 30% at 5.43 MP, and the GI notch costs mean 0.11/255 against render scale's 18.61 — ~170× less picture, because the à-trous filter and the upsample already reconstruct that signal. So the interactive high-DPI default is **native resolution with lighting detail at /3** (`density_defaults`), applied at the first `set_scale_factor` and ONLY when no flag was passed and nothing was saved. `gfx_defaults_auto` is false on every capture path, so bench/screenshot/drill keep the shipped values and no baseline moves; it deliberately does not mark settings dirty, so the derived default follows the display instead of freezing.

Two color targets are mandatory: water samples the scene it blends over, so its destination cannot be its source. And `blit_pipeline` carries a depth-stencil state (it was only ever used inside the water pass) — the standalone upscale needs the depthless `upscale_pipeline`, or the pass invalidates the encoder and EVERY pass in the frame is dropped, which looks like a black window with no HUD rather than a bad blit.

Persistence is a launcher-injected `SettingsStore` (desktop: `data_dir/digblock/settings.json`; web: `localStorage`); precedence is CLI/query > saved > platform default, and non-interactive runs (bench/screenshot/drill) skip load AND save so captures stay hermetic. The last-joined multiplayer name persists here too. `Settings` (digblock-render/src/settings.rs) is serde-free; each launcher owns a serde mirror.

Named local worlds live in `crates/digblock-persist`: the journal (shared `VERSION` — a worldgen retune stales server volumes and client saves together) plus the `WorldStore` trait. Desktop `FsWorldStore` writes the exact server-format journal + state.json with throttled atomic writes; web `LocalStorageWorldStore` uses localStorage (not IndexedDB) because `flush` must run inside synchronous `on_suspend`. Version policy: client saves are **refused, never archived** on mismatch (delete-only in the UI); the `.vN.bak` archive path is server-only.

World UI is in `menu.rs`. In game the root menu reads the same either side — Back to Game, Return to Spawn, Inventory, Alchemy, one exit row, Settings — with Leave World standing where Leave Server does; Singleplayer and Multiplayer belong to the locked title menu, so switching worlds or joining a server goes back through the exit. Both exits share `Engine::return_to_title` (fresh backdrop seed, relocked startup menu); Leave World calls `close_local_save` first and, unlike the disconnect path, runs unconditionally, since even a store-less ephemeral world has a title to return to. `Pipeline`'s optional `EditOverlay` records every `set_block` and re-applies cells before air classification, so local edits survive hard eviction even in unsaved worlds (restored water re-schedules fluid).

## Text

Two embedded TTFs rasterized at runtime with `fontdue` (`digblock-render/src/font/`): a proportional UI face and a monospace one used ONLY by the debug overlay and spike log, which align columns with printf padding. Glyphs are rasterized at the exact pixel size they're drawn at, shelf-packed into one lazily-filled 2048² R8 page, and blitted 1:1 on whole-pixel origins — that 1:1-ness is why the Linear sampler costs nothing and why `glyph_px` no longer snaps to multiples of 8.

Load-bearing rules:

- Sizes are a **layout box height**, never an em, and a text `y` is the box's TOP (`Face::baseline` derives the baseline) — which is what keeps every `(rect.h - glyph) / 2.0` centering site working.
- `Face::run` is the single advance walk behind `measure`, `wrap` and the overlay's `push_text`, so a panel's width and the pen the renderer walks cannot drift (`measure_matches_the_pen_walk`). Never compute a width from a character count.
- The atlas reserves a 4×4 white block whose center is the UV of *every* untextured overlay quad, and only ever repacks in `begin_frame` — a mid-frame reset would invalidate UVs already in the vertex buffer.
- Ink legitimately overflows the nominal box (accents above, descenders below), so anything drawing a backdrop behind text sizes it from `line_h`, not the box.
- The debug panel's width comes from a fixed `DEBUG_COLS` budget with every field printf-padded, NOT from the current frame's longest line — it is right-anchored, so content-derived sizing made it resize and slide on every frame that changed a digit.

`em_ratio` in `font/mod.rs` is the one knob for a font swap; `assets/fonts/SOURCES.md` has the subsetting recipe and the tests that fail if a new face is unsuitable.

## Audio

The engine emits `AudioCmd`s into an injected `Box<dyn AudioSink>` (a `None` sink covers bench/screenshot/drill/iOS). Pure helpers: `digblock-render/src/audio.rs` (materials, footsteps, swim strokes, ambient beds) and `water_audio.rs` (waterfall voice reconciliation). Cadence emitters pace by DISTANCE, not time, so a slow walk or a drifting swim still sounds right; strokes fire only when in water and off the bottom, which is exactly where footsteps stop. Fillers: `apps/desktop/src/audio.rs` (rodio; positional coordinates scaled by `ATT = 0.08` to shape rodio's fixed 1/d rolloff) and `apps/web/src/audio.rs` (WebAudio; one-time pointerdown/keydown `resume()` for Chrome's autoplay rule). SFX are embedded OGGs (`digblock-assets::sfx`, provenance in `assets/sfx/SOURCES.md`). Music is never embedded: the master serves CC0 tracks (`/api/music`) and both fillers fetch at runtime. Mute: `--mute` / `?mute`.

## Browser client

Chrome via wasm32-unknown-unknown + WebGPU (`apps/web`). Query params mirror desktop flags: `?seed= ?tod= ?draw= ?ssr=0 ?overlay ?name= ?mute ?master= ?join&server=`; defaults are full desktop quality; `?master=` defaults to the production master, explicitly empty disables multiplayer + music.

Key mechanics: chunk jobs run inline on the main thread (`workers: 0`); `std::time::Instant` is `web_time::Instant` workspace-wide; GPU init is async (`WaitingForGpu` state); the depth "copy" is a blit into R32Float (WebGPU forbids depth32float as a copy destination); shadow taps use `textureSampleCompareLevel` (Tint's derivative-uniformity rule). Multiplayer: `crates/digblock-net-web` implements `NetTransport` over WebTransport with `serverCertificateHashes` from the master; the server's self-signed cert is 10-day validity (Chrome caps pinned certs at 14 days) and rotates in-process every 7, re-registering so the master hands out the fresh pin. `apps/web/src/services.rs` is the fetch()-based `MenuServices` filler. Scripted joins go through `EngineConfig::auto_join`, which walks the real menu path. Screenshots, bench, drill, and metrics CSV are native-only.

Deploying: `just build-web` is the bundle, and `deploy-web.yml` runs that recipe rather than mirroring it, because the recipe owns a correctness invariant a copy would drift from. The glue JS and the wasm are one artifact (wasm-bindgen mangles import names with a per-build hash), so a browser pairing fresh wasm with stale glue dies at load with `LinkError: ... requires a callable`. **Cache headers cannot fix this** and twice appeared to — the CDN in front of the custom domain rewrites Cache-Control for `.js` and not for `.wasm`, reintroducing the same fatal pairing one layer out. The fix is naming: both files carry the same content stamp, only the always-revalidated `index.html` knows it, and `_headers` just declares the pair immutable. A stale index can therefore only 404 on a pair that no longer exists — self-healing on reload — never link half of a live one.

## Architecture

Workspace with eight crates, two thin app launchers, and a dedicated server. The crate boundaries are load-bearing:

- **`crates/digblock-core`** — pure game logic (worldgen, chunks, meshing, fluid, player physics, input driving, sun, metrics). No GPU or windowing deps; everything testable headless.
- **`crates/digblock-platform`** — the winit shell around a headless-tested lifecycle state machine (`lifecycle.rs`), input translation, screenshot capture. The **only** crate allowed to touch `winit` or `wgpu::Surface`. Defines the `Game` trait and `Gpu` (process-lifetime device/queue).
- **`crates/digblock-render`** — the engine: world state + wgpu renderer, implements `Game`. Renders into `&TextureView`s borrowed per `render()` call and never sees the surface, so it can't hold a stale swapchain texture across a suspend. `engine.rs` (state/streaming/orchestration) + `renderer.rs` (device-lifetime state, passes) + per-system modules (`sky.rs`, `water.rs`, `spray.rs`, `players.rs`, `overlay.rs`, `menu.rs`/`chat.rs`, `audio.rs`/`water_audio.rs`, `smoothing.rs`, `item_geom.rs`/`viewmodel.rs`, `ui/`).
- **`crates/digblock-assets`** — compile-time embedded textures, WGSL, and the two UI typefaces (byte-identical on every platform). Shaders are naga-validated by a test, so WGSL errors surface without a GPU.
- **`crates/digblock-net`** — protocol + client netcode, **sans-IO** (wasm-clean). Postcard wire format, append-only evolution, `PROTOCOL_VERSION` bumped on breaks. Holds the movement predictor, pending-edit tracking, remote-player interpolation, and a loopback transport for plain `cargo test`.
- **`crates/digblock-net-native`** — wtransport (WebTransport/QUIC) on a background thread, bridged over non-blocking channels. Only desktop and the bot link it.
- **`crates/digblock-persist`** — persistence shared by server and client saves: journal format (index/codec/snapshot wasm-clean; file writer + compaction cfg'd native), `WorldStore` trait, `FsWorldStore`. Sits above core AND net. Web store impl lives in `apps/web/src/store.rs`.
- **`apps/desktop`**, **`apps/ios`** — thin launchers. Desktop also owns the menu's HTTP services (`services.rs`); the engine only sees `MenuServices` channels.
- **`apps/server`** — headless dedicated server. Authoritative 60Hz sim (`sim/`, socket-free, tested by injected events), wtransport layer (`net.rs` — verifies join tokens with the master before the sim hears about a connection), master HTTP client (`master.rs`), chunk store, append-only edit journal with boot compaction (terrain is never sent; join sync = seed + edits; old-version journals archive to `.vN.bak` — this destructive path is server-only).
- **`apps/master`** — .NET 10 minimal API (BCL only, not in the cargo workspace). In-memory registry + one-time token store; verifies reachability with a mandatory QUIC probe pinned to the registered cert hash (no probe-off mode; hosts without UDP egress or libmsquic fail at boot). The Rust e2e tests boot its real container. Never put `Urls` in appsettings.json — it overrides `ASPNETCORE_URLS` and breaks the container bind. The HTTP contract in `Contracts.cs` is mirrored by `apps/server/src/master.rs` and `apps/desktop/src/services.rs` — change all three together.

### Multiplayer model

Joining is token-only: client gets a one-time token from the master (`POST /api/join`), sends it in `Hello`, the server consumes it via `POST /api/tokens/verify` (the master's display name wins). Verification fails **closed**; connected players are unaffected by a master outage.

Server-authoritative everything, but movement uses an **adoption envelope**: clients send per-tick inputs plus claimed post-tick state; the server runs the same `Player::tick` and adopts claims within `POS_TOLERANCE` that aren't inside geometry — honest clients never drift or rubber-band. A time-integrated EWMA of claim−sim deltas (`DRIFT_ALPHA`/`DRIFT_TOLERANCE`) suspends adoption under sustained directional bias, closing the edge-riding exploit. Rejected claims are corrected by the next snapshot via rewind/replay, surfaced as a ~200ms decaying camera offset, never a snap.

The camera is presentation-only in two more ways, both visual-only — gameplay (occupancy via `body_pos()`, the wire, saves) always reads the authoritative `Player::pos`: it interpolates between the last two 60Hz tick states (`smoothing.rs`; without it frame-pacing jitter *is* position jitter, measurably the dominant stutter source — see NET-AUDIT.md), and a rewind must carry the lerp anchor with it. `NetEvent::Ack` is dispatched ahead of `pump_net`'s edit-budgeted queue: it has no ordering dependency on edits, and an ack delayed past the predictor's `BUF_CAP` (2.1s) forces every later snapshot down the replay path. Dig/place is predicted locally and validated server-side by re-raycasting from the claimed origin. Fluid runs only on the server; results broadcast as ordinary edits. Protocol constants live in `digblock-net/src/protocol.rs`.

**Items** (protocol v10, extended in v12): the hotbar plus a 36-slot inventory grid (`digblock-core/src/inv_grid.rs`) are player-authored *assignments* over the count-based inventory — a type lives in exactly one slot, kept coherent by `reconcile_layout` (deterministic, run identically client- and server-side after every count change). The arrangement rides `ClientMsg::Layout`/`ServerMsg::Layout` on the reliable stream (in-order with edits, via the action queue) and persists per identity in the server's `player_store` (`inventories.bin` v3; v1/v2 read-compat — never wiped) and in local saves' `state.json`. Enforcement: `EditRequest.slot` declares the hotbar slot used, and Place/Collect must match its item (`RejectReason::WrongSlot`) — honest clients can't race it because Layout precedes the edit on the same stream. Snapshots carry each player's held item (`NetPlayerState.held`), rendered on remote players as a small textured cube. A slot whose count reaches zero is **released**, not greyed; that is safe only because the engine reconciles and mirrors the layout BEFORE the frame's clicks send edits.

**Tools** (SKILLS-DESIGN §6): item-only `blocks!` rows (`BlockType::Bucket`; `is_tool`, `always_owned`) — never rendered, placed, or slotted. The tool slot is PINNED to the bar's last position (a legacy mid-bar layout migrates on `Hotbar::from_wire`); WHICH tool it holds is `Hotbar::active_tool`, carried as the Layout wire's 9th entry, so a cycle-then-scoop validates in wire order and the server's gates check `active_tool == Bucket`. Tapping 9 with the tool slot already selected cycles the owned roster (`Engine::owned_tools`, block-id order); `hud::tool_rail` draws the non-active owned tools faded right of the bar, only once a second tool exists.

**The water tool is stateful** (protocol v12), and its charge is stored as the inventory's Water count — capped at one by `inventory::cap`, named by `Inventory::bucket_full`. Storing the charge in the inventory rather than a field of its own is the load-bearing decision: prediction, rejection rollback (`inv_delta`), `InventoryFull` rebase and both persistence formats then carry it with no new machinery. Water is no longer an item — `is_slottable` is false and `reconcile_layout` sweeps it out of bar and grid whatever the count says, which both keeps it off the item screens and *is* the migration for saves written when it was a stack (a legacy stack decodes to one full bucket, never a windfall). **Empty**: the fluid-aware ray (`scoop_ready` picks it), left-click holds to scoop, right-click does nothing. **Charged**: the ordinary ray — so the crosshair highlights normal blocks again — left-click does nothing at all, right-click pours through the ordinary `apply_place` path where the stock debit is what empties it. The pour only works because the ray switched: the fluid ray stops INSIDE a source, leaving no face normal to build against. Server-side both halves are one affordability gate — `RejectReason::BucketFull` for a scoop with no room (refused BEFORE the world write, so a full bucket can't delete the spring for nothing), `NoStock` for a pour with no charge — and `WaterTool` is the only slot that may place water. The charge is geometry, not a tint (`item_geom::bucket_faces`), so it reads in the hotbar icon, the hand, and on remote players; `viewmodel::same_item` deliberately treats the two states as one item so filling the bucket doesn't dip the hand like a slot change.

**Your own held item is the viewmodel** (`viewmodel.rs`): authored in view space with its own 55° projection, so no camera basis, no world-FOV coupling, and no near-plane clipping. It draws in a fifth pass between water and overlay that CLEARS the shared depth attachment (the water pass discards it anyway) — that is what makes the item immune to walking into a wall while still self-occluding, which a non-convex item like a staircase needs. Geometry comes from `item_geom.rs`, the one authority shared with the inventory icons; corners follow `mesher::face_corners` because both paths draw through `mesher::quad_indices`. The bob paces off horizontal distance (like `Footsteps`) and is advanced in `update`, NOT `step_audio`, which early-returns with no audio sink and would freeze the hand in exactly the runs that photograph it. `Swap` owns which item is DRAWN — it lags `hotbar.selected` by half a dip so the exchange happens below the frame.

### Blocks (core/block.rs)

Block behavior is data-driven via the `blocks!` macro — one row produces the `repr(u16)` enum, `COUNT`/`ALL`, and the `PROPS` table together, so they can't skew. Rows hold `RenderClass` (None/Opaque/Cutout/Translucent/Shaped), `collides`, per-face texture layers, and `MeshBucket`; water is a block family driven by `FluidProps` data. Adding a block = one row + PNG + `LAYERS` entry.

The layer index is RUNTIME ONLY (mesh vertex bits, never the wire or a save), so the list may be reordered — what it may not do is drift from `digblock_core::block::tex`, which mirrors it position for position and would silently texture blocks with each other's PNGs; a `const` assert in `digblock-render/src/texture.rs` (the only file that sees both crates) fails the BUILD on a length skew.

Texture vocabulary: **`LOG`/`LOG_TOP` is the tree** (bark, cut-end rings) and the **`LUMBER_*` set is planed timber** — the material crafted things are made of (`LUMBER_LIGHT` is the joinery — the bucket, the torch post, and the `Lumber` block with its stairs, slab and door; `LUMBER_DARK` and `LUMBER_RED` are registered and unwired, the obvious second and third timbers). Calling both "wood" is what made it unclear which one a row was asking for. `Log.png` is seam-fixed for VERTICAL tiling (trunks stack); `GrassSide`/`DryGrassSide` deliberately do NOT tile vertically (dirt below, green fringe above), so a blanket tiling test is not possible. Derived textures come from the checked-in `tools/texgen`, outputs committed — a run rewrites EVERY output, and the noisy recipes share one rng, so adding or removing a `save` rerolls the noise in everything after it.

Chunk cells are `u16` end-to-end: 10-bit id, spare bits 10–11, STATE nibble in 12–15, travelling wire and journal as-is (protocol v8, journal v3). Mesher, physics, fluid, and raycast all key off the tables — no per-block special cases elsewhere.

### Sub-block shapes (core/shapes.rs)

Shaped blocks live on a **12×12×12 sub-grid** (12 divides by 2/3/4/6), geometry STATIC per (block id, state nibble) — no per-instance micro-voxels. `shapes.rs` authors each shape as sub-box lists in a canonical +x facing and bakes every variant at first use (rotate → rasterize → greedy-merge; pure integer, deterministic) into render quad templates, boundary coverage masks (`FaceMask`, the culling currency), collision boxes, and interaction boxes. Per-shape geometry lives in `shapes.rs` comments and pinned tests — don't re-document it here. `state_valid` is THE wire gate for state bits; `Facing` is axis-named (`Dir::West` is +x — compass names are a trap).

Mesher: shaped cells stamp templates via `emit_shaped`; boundary quads cull against `neighbor_cover`; `MAX_SHAPE_QUADS` (test-pinned per variant) sizes the renderer's `MAX_QUADS`. Vertices pack positions in twelfths (8 bits/axis); shaders decode with an integer whole/remainder split so lattice points stay exact under GPU fast-math — chunk.wgsl and water.wgsl must always agree.

Physics (SIM v10): stairs collide as a **diagonal ramp** (`RAMP_SNAP_*`; beyond the band or pinched under a low ceiling they revert to their boxes and block like walls; the run-out lets a flight mount the flush cube it tops out against, mirrored in `overlaps_solid` so mid-mount claims stay adoptable). A ramp supports only from its low front edge on, and the downhill glue takes the highest surface underfoot only when it is below the feet — together those make a flight one continuous climb (`stair_flight_climbs_at_a_constant_rate`). **Auto-step** (`AUTO_STEP_MAX` = 4/12 + ε): a descending walk mounts any Cube/Boxes top within a third of the feet when there's capsule headroom; ramps are structurally excluded and doors stay unwalkable via the headroom probe alone. A step and a stair are deliberately the same motion — the mount rises at `MOUNT_RATE` (= `WALK_SPEED`, exactly what a 45° ramp gives a walk), so the tick lerp draws it smoothly with no presentation special case. Never rate-limit a *landing*, which is why `step_contact` takes only descents slower than the mount climbs. `step_mount` is the one position-only predicate the resolver, `grounded` and `overlaps_solid` all read (it requires the axis be OFF the box — a mount is an approach from the side). `overlaps_solid`/`placement_blocked` are the shape-aware occupancy contract shared by client place-rejection, the server's InsidePlayer scan, and the adoption envelope's probe — standing on a shaped block is NOT "inside solid". Raycasts narrow-phase against collision boxes (miss → DDA continues); `raycast_interact` uses interaction boxes so open doors stay clickable.

Right-click is use-beats-place: an interactable under the ray toggles via `EditKind::Interact`, which rides the whole existing EditRequest validation/rate-limit/queue machinery (the server flips both door halves). Multi-cell shapes place/dig as a pair written lower-first in one tick, client-predicted under one seq via `PendingEdits::begin_multi`; per-cell LWW journal replay keeps pairs consistent. v1 limits (documented, deliberate): shaped blocks float when support is dug, fluid treats them as solid, water emits no face against them.

The **planed-timber set** (`Lumber` + `LumberStairs`/`LumberSlab`/`LumberDoor`, all `LUMBER_LIGHT`) is §7.2's material × shape grid in miniature: the whole set unlocks at the MATERIAL's level (Alch 15), not at each shape's own, which is what makes a material read as a material. The `Lumber` block exists because its slab has to have something to complete into. The door is a lumber item too — it was `WoodDoor` in dark timber at Alch 10, and joined the set when the material arrived (the id, 24, is unchanged; the rename is source-only).

**Stackable slabs** (Wood/Stone/LumberSlab): thirds anchored to one end of their cell — state bit 0 = two-thirds, bit 1 = anchored to the ceiling instead of the floor (`slab_state`/`slab_is_top`). `slab_place_state` keys on the hit normal alone, never a cursor position, which would have to survive client and server rays agreeing to the twelfth. Placing onto a same-material slab's OPEN face (`slab_grow_normal`) grows the hit cell in place (`slab_grown`: 1/3 → 2/3 → the plain base block, anchor carried along); cross-material hits and hits on the flush face place a fresh 1/3 in the neighbour cell. The wire always carries the canonical state-0 cell and the server re-derives BOTH the grow and the anchor from its own raycast (a client-sent state ≠ 0 is BadBlock; slot/stock gates key on the requested slab even when the written cell is Wood/Stone). The two anchors are exact mirrors, so one item, one dig time and one alchemy cost serve both (`a_ceiling_slab_is_a_floor_slab_mirrored`). Digging shrinks one third per completed hold (`slab_shrunk` keeps the anchor, so a hanging slab never drops mid-removal), one slab credit each; `DigState`/`DigProgress` track the FULL cell, so a grow landing mid-hold resets the timer. The economy closes exactly: slab = 9 sub-units, 3 × 9 = 27 = one block. You can't grow the cell you stand in (InsidePlayer — step off first).

### Spawn & protected cells (core/spawn.rs + core/protect.rs)

Both modules carry thorough `//!` docs: the two-layer design (seed-only `anchor`, edit-aware `resolve`), why the search anchors at the pristine spawn and never descends, that nothing is persisted, and protect's one-predicate rule. What those don't say, and what bites:

- **The `Edits` view is edits only, never a chunk store.** A store answers `None` for non-resident cells and the support test reads `None` as "trust worldgen", so wiring one in makes unloaded columns read as void. The server's journal is the correct and complete source, fluid included.
- **The anchor's acceptance test is a level disc** — every column within `CLEAR` at exactly `h`, dry, not a cave mouth, nothing in the `CAPSULE` cylinder above — and level in *both* directions, since the original rule ignored neighbours below `h` and spawns could perch on the lip of a drop. Level is also what makes `edits_clear`'s rules absolute and keeps the overlay-empty search bit-identical to the pristine walk. The pins assert against worldgen directly (`every_anchor_stands_on_level_ground_under_open_sky`, `resolve_with_no_edits_is_the_anchor`, golden `spawn_positions_are_pinned`), because a test that only asks whether spawn *moved* cannot catch a bad destination.
- **`spawn::lock_region` is exactly the cell set the search inspects**, and `stands_clear` reads exactly those cells (`lock_region_covers_what_the_test_reads`, `stands_clear_reads_exactly_the_locked_region`). That equivalence is why a locked spawn is permanently valid and why `Sim::spawn_point` skips the search when locked; `/lock-spawn on` resolves first and locks around the **result**, so it can't freeze an already-broken spawn. `/set-spawn` validates with the same predicate, which reads the world as it *is* rather than pristine worldgen, and deliberately skips `SPAWN_FLOOR` — an operator aiming at a block has made a choice, and the water rule is what keeps a hand-picked spawn out of the sea.
- **Protection refuses the fluid *write*, not the schedule** — that is what stops water sourced outside a locked region flowing in. Rejections are `RejectReason::Protected` (protocol v11); the client picks dig-vs-place wording from `PendingEdit.inv_delta`'s sign, NOT `placed == Air`, which a slab dig breaks. A protected hold is refused at `DigStart` (`ServerMsg::DigRefused`) rather than at the completing edit, so the player isn't left holding the button through a full dig timer, and `refused_cell` stops `step_dig` reopening it every frame.
- **Rejoin resumes in place**, through the same `clear_landing` rule as a spawn: `PlayerRecord` carries the last eye position *and* the return-to-spawn tick, since position alone let a rejoin clear the cooldown. `/set-spawn-dir` rides `Welcome.spawn_look` and `Teleported.look` (protocol v13), but a resume always sends zero, and the client's feed line keys on `spawn_return_pending` rather than on whether a facing came back.

### Worldgen (core/worldgen/ + decoration.rs)

Everything is a pure function of `(x, z, seed)` — column content never depends on generation order. Stages: `terrain.rs` (continentalness/roughness/ridge/detail control fields, tuning in `TerrainParams`, terraced erosion), `rivers.rs` (channels from the zero band of a warped field, meeting the sea at grade), `lakes.rs` (sparse bowls in flat inland country; lake beats river per column), `caves.rs` (intersection of two 3D-noise bands, land only), `classify.rs` (per-column `SurfaceKind` + climate biomes, block rules/tree density/species as `SurfaceProps` table data; climate shifts the lines and picks the biome, never the terrain). `SEA_LEVEL = 128` of a 256-block world.

Structures are a decoration pass using pure apron evaluation: per-family salted position hashes (`structures_near`), every chunk within `STRUCTURE_APRON` computes identical structures independently, so they span borders with no pipeline state; trunk roots are the single exception to decoration's write-into-Air-only rule. Sky chunks resolve to the shared `AIR_CHUNK` sentinel Arc (never meshed, recognized by pointer).

### Chunk pipeline (core/pipeline.rs + mesher.rs)

The main thread owns the chunk store and scheduling; workers run pure functions (terrain gen, meshing) over immutable snapshots — a mesh job gets a padded 18³ copy of its chunk (one-block shell from all 26 neighbors, feeding water corner heights). Staleness is handled by generation counters: results whose `gen` doesn't match are dropped; a new chunk bumps its own and affected Ready neighbors' counters. Edits go through `Pipeline::set_block`/`set_cell` (copy-on-write via `Arc::make_mut`, bumping only neighbors whose shell contains the edit). Vertices are two u32 words: word 0 geometry (positions in twelfths), word 1 material (10-bit texture layer, `MAX_TEX_LAYERS` = 1024; water carries its surface/flow payload in the upper bits).

**Water surface knitting** is the subtle part; the rules are commented at the code. `mesher/water.rs::corner_drop` is a pure function of the horizontal lattice corner — never of the cell emitting the face — which is what lets two cells sharing a corner agree and knit without a crack, including across chunk borders. Its pins, in order: water above or a covered cell → full; an air cell with water below → plunge the whole block, UNLESS a resting source touches the corner; else 9 − the **strongest** touching amount. Strongest, not the mean: the sim halves on spread (8 → 4 → 2 → 1), so averaging drags every corner toward the thinner water beyond it, while the max makes each cell's top face span exactly from its uphill neighbour's level to its own. `water.wgsl` then maps that code to a height **linearly** (`d / 9`) — the two halves are one invariant, and a hand-tuned curve simply falsifies the codes the sim computed, so any change to how corners are chosen must be checked against the mapping and not just the codes. The source-beats-plunge pin is separate and still needed: only water resting on a **colliding** block spreads outward at its own level (sources included), so a bucket emptied against a wall face is ringed by air over the pool it just poured — the plunge trigger on all four corners at once, which without the pin loses the block's top face and skips every side as zero-area.

### Lifecycle robustness

Suspend/resume and device-loss are standing regression targets for a future Android port. `Renderer::new` is a pure constructor so device-loss recovery is "build a new one and re-upload meshes" (`Game::rebuild_gpu_resources`). `Game::on_suspend` must be cheap and synchronous — the process may be killed with no further callbacks. Test via `just run --drill` or F9/F10 at runtime; F8 screenshots.
