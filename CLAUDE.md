# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Rust + wgpu rewrite of the DigBlock voxel engine (originally Java/libGDX, 2015–2017). The initial port matched the Java original faithfully (in places bit-exactly), but that goal is complete — the engine is now free to diverge and improve. The old Java repo at `../DigBlock` remains a useful behavior reference, not a constraint.

## Commands

```sh
just run                  # run desktop app (cargo run -p digblock-desktop)
just run --drill          # automated lifecycle drill (suspend/resume + device-loss)
just bench                # deterministic perf run: release build, scripted camera flight,
                          # inputs disabled, vsync-paced, CSV to bench.csv, summary line
                          # (fill time + frame-pacing counts) on exit; add --no-vsync for
                          # uncapped raw-cost percentiles; findings live in BENCH.md
just check                # full gate: cargo fmt --all --check, clippy -D warnings, cargo test --workspace
                          # (needs Docker running: the server e2e tests boot the apps/master
                          # deployment container — alpine + libmsquic — with real QUIC probing)
just check-ios            # cargo check -p digblock-ios --target aarch64-apple-ios (no Xcode needed)
just web                  # browser client: wasm build + serve at http://localhost:8080 (Chrome/WebGPU;
                          # needs `cargo install wasm-bindgen-cli` at Cargo.lock's exact version)
just check-web            # clippy for wasm32-unknown-unknown (web, render, platform) — no CLI tools needed
just play-web             # master container + native server + web bundle served; open the printed
                          # URL, pick Multiplayer, join — or append &join for the scripted flow
just ios-sim              # simulator build+run (requires full Xcode)
just ios-device           # device build (requires full Xcode)
just master               # .NET master server run natively (for iterating on its code); the
                          # mandatory QUIC probe needs `brew install libmsquic` — otherwise
                          # use the container (just play builds + runs it automatically)
just server               # dedicated multiplayer server (headless; journal persists in ./data);
                          # REQUIRES --master-url + --advertise-host — joining is token-only
just bot -- --bots 4      # headless bots: pick a server from the master's list, mint tokens, join
just compose wifi         # dockerized master + server behind tc netem (clean | wifi | cellular)
just profile              # release-speed build with debug symbols (Instruments/profilers)
just compose-bots wifi    # same + 4-bot soak, exits non-zero on missed snapshots
```

Multiplayer is master-first with **no direct-connect path**: the .NET master (`apps/master`) lists servers, distributes cert pins, and mints one-time join tokens; a game server refuses any Hello whose token it can't verify with the master. `just play` runs all three (containerized master with the real QUIC probe + native server + client opening at the main menu — pick Multiplayer, type a name, join "Local World"; closing the window stops everything). Display names are mandatory and validated everywhere (3-10 chars of `a-z A-Z 0-9 - _` — one canonical `validate_name` in `digblock-net/src/protocol.rs`, mirrored as the regex backstop in the master's `/api/join`; the menu field is never pre-filled, `?name=`/`--name` are explicit validated overrides). In-game chat: T or Enter opens the input line (pointer lock stays held via `Game::wants_text_input`), Enter sends, Escape discards; the server sanitizes to printable ASCII, token-bucket rate-limits (`CHAT_*` in protocol.rs), and broadcasts to everyone including the sender. Remote players carry name tags (CPU-projected into the overlay, 32-block range, no depth test). Register supports an optional `probeHost` separate from the advertised host for NAT-split dev topologies: locally the server advertises `127.0.0.1` (what clients dial) and the containerized master probes `host.docker.internal` — the container's only stable UDP path to the host; a LAN-IP hairpin breaks QUIC address validation under Docker's NAT. Production servers omit `probeHost`. Extra windows: `just run -- --master-url http://127.0.0.1:5200` (menu; Escape reopens it in-game) or with `--join --name <name>` to skip the menu for scripted flows. Use `127.0.0.1`, not `localhost` — macOS resolves `localhost` to `::1` and the game server binds IPv4 only. A desktop client can also play against the *containerized* stack — `just play-docker [clean|wifi|cellular]` (netem shapes the real client). Host↔container UDP/QUIC works fine (Docker Desktop with "Use kernel networking for UDP" enabled); if the client times out, check the server container's logs before suspecting the network — a server that died at boot looks identical from the client side.

Run a single test: `cargo test -p digblock-core --test worldgen` (integration test file) or `cargo test -p digblock-core <test_name>`. CI is **intentionally disabled** pre-deployment (`.github/workflows/ci.yml.disabled`); when re-enabled it runs the same steps as `just check` plus desktop and iOS builds, with clippy warnings failing the build. Until then, `just check` + `just check-ios` are the gate.

Deterministic-capture / metrics flags for `just run`: `--seed <f64>`, `--tod <deg>` (freezes the sun), `--screenshot out.png`, `--frames N`, `--exit`, `--metrics-csv out.csv`, `--overlay` (start with the debug overlay on; backquote toggles it at runtime), `--no-vsync` (uncapped present), `--workers N`, `--draw-dist N`, `--mobile` (draw dist 10, 1024px shadows — the iOS config).

Metrics (`digblock-core/src/metrics.rs`) collect per-phase CPU frame timings, GPU pass ms via timestamp queries (feature-detected), chunk-pipeline job timings/queue gauges, and renderer draw stats; everything lands in the 5s log line, the CSV, and the toggleable on-screen overlay (`digblock-render/src/overlay.rs`, zero cost when hidden). Frame-pacing diagnostics: the bench is vsync-paced by default (`--no-vsync` for uncapped raw cost), and `DIG_SPIKELOG=1` logs per-phase breakdowns of frames over the 120Hz budget. Main-thread streaming work (result drain + mesh uploads) is time-budgeted per frame (`STREAM_BUDGET_MS` in engine.rs) and the wide shadow cascade re-renders sliced across frames into a ping-ponged back map, so streaming throughput cannot hitch the render loop.

Formatting uses hard tabs, max width 100 (`rustfmt.toml`).

### Audio

The engine emits `AudioCmd`s (listener pose, positional one-shots, loop voices with move/pitch/stop, pause/resume) into an injected `Box<dyn AudioSink>` — the `MenuServices` pattern again, so the engine stays platform-free and a `None` sink (bench, screenshot, drill, iOS) is a single branch. Vocabulary + pure helpers live in `digblock-render/src/audio.rs` (block→material mapping, footstep cadence, ambient-bed hysteresis) and `water_audio.rs` (waterfall voices reconciled from the same mesh-impact cells spray renders: nearest-first clustering, K=4 voices, move-don't-restart matching, 1 s stop grace). Fillers: `apps/desktop/src/audio.rs` (rodio on an `"audio"` thread; `SpatialSink` per positional voice with all coordinates scaled by `ATT = 0.08` to shape rodio's fixed 1/d rolloff) and `apps/web/src/audio.rs` (WebAudio node graph applied synchronously; decode-once with a pending queue; one-time pointerdown/keydown listeners `resume()` the context for Chrome's autoplay rule). SFX are embedded mono OGGs in `digblock-assets::sfx` (provenance: `assets/sfx/SOURCES.md`; magic-bytes test). **Music is never embedded**: the master serves CC0 tracks (`GET /api/music` manifest + `/music/{file}`, files in `apps/master/music/`) and both fillers fetch them at runtime — desktop via ureq on the fetch thread, web via `fetch()` — so even single-player has music whenever a master URL is configured. Mute: `--mute` / `?mute`.

### Browser client

The client runs in Chrome via wasm32-unknown-unknown + WebGPU (`apps/web`, query params mirror desktop flags: `?seed= ?tod= ?draw= ?ssr=0 ?shadow= ?overlay ?name= ?mute ?master= ?join&server=` — defaults are full desktop quality, params opt weaker hardware down). Key mechanics: chunk jobs run **inline on the main thread** (`Pipeline` `workers: 0` selects the inline executor at runtime — also reachable natively via `--workers 0`); `std::time::Instant` is `web_time::Instant` workspace-wide; GPU init is async on wasm (`WaitingForGpu` app state + winit user event); the depth "copy" is a fullscreen blit into an R32Float target because WebGPU forbids depth32float as a copy destination; shadow taps use `textureSampleCompareLevel` (Tint's derivative-uniformity rule). Multiplayer: `crates/digblock-net-web` implements `NetTransport` over hand-written WebTransport bindings (`serverCertificateHashes` = the master's cert pin; the server's self-signed cert is 10-day validity because Chrome caps pinned certs at 14, and the server rotates it in-process every 7 days — `reload_config` swaps the cert without touching live connections, then re-registers so the master hands out the new pin; long-running servers never need a restart for cert freshness); `apps/web/src/services.rs` is the fetch()-based `MenuServices` filler (pings time a throwaway WebTransport handshake per server — the same measurement as the native QUIC probe); the master's two client endpoints allow any CORS origin. Scripted joins go through `EngineConfig::auto_join` — the menu walks the exact user path, so `MenuResponse::Connect` needs no special case. Screenshots, bench, drill, and metrics CSV are native-only (cfg'd out).

## Architecture

Workspace with six crates, two thin app launchers, and a dedicated server. The crate boundaries are load-bearing:

- **`crates/digblock-core`** — pure game logic (worldgen, chunks, meshing, fluid rules, player physics, touch/input driving, sun, metrics). No GPU or windowing deps; everything is testable headless.
- **`crates/digblock-platform`** — the winit shell (`app.rs`) around a pure lifecycle decision core (`lifecycle.rs` — a headless-tested state machine turning OS/drill/surface events into ordered shell actions), input translation, screenshot capture. This is the **only** crate allowed to touch `winit` or `wgpu::Surface`. It defines the `Game` trait and the `Gpu` struct (process-lifetime device/queue).
- **`crates/digblock-render`** — the engine: world state + wgpu renderer. Implements `Game`. It renders into `&TextureView`s borrowed for a single `render()` call and never sees the surface, so it cannot hold a stale swapchain texture across a suspend on any platform. Split into `engine.rs` (world state, streaming, frame orchestration) and `renderer.rs` (device-lifetime state + pass structure), with per-system modules: `shadow.rs` (two-cascade system incl. the wide ping-pong), `sky.rs`, `water.rs`, `spray.rs`, `players.rs`, `overlay.rs`, `pipeline_builder.rs`, `menu.rs`/`chat.rs` (pure input state machines), `audio.rs`/`water_audio.rs` (the audio seam — see Audio above).
- **`crates/digblock-assets`** — compile-time embedded textures and WGSL shaders (`include_bytes!`/`include_str!`), so every platform gets byte-identical assets. Shaders are naga-validated by a test, so CI catches WGSL errors without a GPU.
- **`crates/digblock-net`** — multiplayer protocol + client netcode, **sans-IO** (no tokio/sockets — wasm-clean; a future browser client implements the same `NetTransport` trait over the WebTransport JS API). Wire format is postcard, append-only evolution, `PROTOCOL_VERSION` bumped on breaks. Holds the movement predictor (rewind/replay reconciliation), pending-edit tracking (authoritative-beats-pending precedence), remote-player interpolation, and an in-memory loopback transport that makes all of it plain-`cargo test`-able.
- **`crates/digblock-net-native`** — the native transport driver: wtransport (WebTransport/QUIC) on a detached background thread, bridged over non-blocking channels. Only `apps/desktop` and the server's bot link it; iOS is untouched.
- **`apps/desktop`**, **`apps/ios`** — thin launchers (arg parsing / staticlib entry). Desktop also owns the menu's HTTP services (`services.rs`: list fetch, ping probes, token mint + connect) — the engine only sees `MenuServices` channels.
- **`apps/server`** — headless dedicated server (lib + `digblock-server`/`bot` bins). Authoritative sim on one 60Hz thread (`sim/`, socket-free and fully tested by injected events), wtransport net layer (`net.rs` — also decodes the first Hello frame and verifies its token with the master before the sim hears about the connection), master HTTP client (`master.rs`: register with retry, heartbeats + player counts, verify, shutdown notify; env fallbacks `DIGBLOCK_MASTER_URL` etc.), multi-center no-mesh chunk store (`store.rs`), append-only edit journal with boot compaction (`journal.rs` — terrain is never sent; join sync = seed + edits; a journal from an older format version is archived to `.vN.bak` at boot and the world starts fresh).
- **`apps/master`** — the .NET 10 minimal API master server (BCL only, NOT in the cargo workspace). In-memory registry + one-time token store; verifies game-server reachability with a mandatory QUIC handshake pinned to the registered cert hash (`Probe.cs` — no probe-off mode exists; a host that can't QUIC, e.g. macOS without `brew install libmsquic`, fails at boot); background health checker culls dead servers. Deploys as the container in its `Dockerfile` (linux + libmsquic — the well-trodden System.Net.Quic path; App-Service-style hosts with no UDP egress can't run the probe). The Rust e2e tests boot exactly that container and register through its real probe via `host.docker.internal`. Never put `Urls` in appsettings.json — it would override `ASPNETCORE_URLS` and break the container's 0.0.0.0 bind. The HTTP contract lives in `Contracts.cs` and is mirrored by `apps/server/src/master.rs` and `apps/desktop/src/services.rs` — change all three together.

### Multiplayer model

Joining is token-only: the client asks the master for a one-time 16-byte token (`POST /api/join` with a display name), sends it in `Hello`'s existing `token` field (no wire change), and the game server consumes it via `POST /api/tokens/verify` — the master's display name overrides the claimed one. Verification fails **closed** (master down ⇒ new joins refused; connected players are unaffected). Server-side, tokens are checked in `net.rs` before the sim ever sees the connection; the sim itself is master-unaware.

Server-authoritative everything, but movement uses an **adoption envelope**: clients send per-tick inputs *plus* their claimed post-tick state; the server runs the same `Player::tick` and adopts the claim when it's within `POS_TOLERANCE`, sanely displaced, and not inside geometry — so honest clients never accumulate drift and never rubber-band. A second, time-integrated gate closes the edge-riding exploit: the server keeps an EWMA of each adopted claim's (claim − sim) delta *vector* (`DRIFT_ALPHA`, ~2 s window); honest deltas are zero-mean float noise and cancel, while sustained directional bias trips `DRIFT_TOLERANCE` within ~6 ticks and suspends adoption until the average decays — capping cheat gain at ~1.2 blocks/s sustained (vs 4 walking). Out-of-envelope claims keep the server's state and the next snapshot corrects the client (rewind/replay, surfaced as a ~200ms decaying camera offset, never a snap). Dig/place is predicted locally, validated server-side by re-raycasting from the claimed origin (`EDIT_POS_TOLERANCE` vs the server's player position), and confirmed or reverted. Fluid runs only on the server; results broadcast as ordinary edits. Protocol constants live in `digblock-net/src/protocol.rs`. `DIG_PLAYERBOX=1` renders a fake remote player 5 blocks ahead (GPU-path check without a second client).

### Java heritage

The port was originally validated bit-exactly against the Java original; those parity tests have been retired, and behavior — including terrain produced by a given seed — has since diverged substantially (256-block world, shaped terrain, caves, trees, dig/place). Comments citing Java code explain provenance, not obligations.

### Blocks (core/block.rs)

Block behavior is data-driven and generated by the `blocks!` macro — one row per block produces the `repr(u16)` enum, `COUNT`/`ALL`, and the `PROPS` table together, so they cannot skew. Each row holds the block's `RenderClass` (None/Opaque/Cutout/Translucent), `collides`, per-face texture layers, and mesh bucket (`MeshBucket`); water is a block *family* (source, `WaterFlow1..7`, `WaterFall`) whose behavior is `FluidProps` data. Adding a block = one `blocks!` row + PNG + `LAYERS` entry in digblock-assets (layer order is append-only); derived textures are generated by the checked-in `tools/texgen` (`cargo run -p texgen`, outputs committed). Chunk cells are `u16` end-to-end — 10-bit block id plus spare bits, travelling the wire and the journal as-is (protocol v5, journal v3). The mesher, physics, fluid, and raycast all key off the tables — no per-block special cases elsewhere.

### Worldgen (core/worldgen/ + decoration.rs)

Everything is a pure function of `(x, z, seed)` — column content never depends on generation order. The module splits by stage: `terrain.rs` (control fields — continentalness picks base elevation through a spline, roughness gates where mountain relief appears, a ridge field draws the ranges, detail fBm adds local relief; all tuning lives in `TerrainParams`; strongly eroded mid-altitude country terraces into treads and risers), `rivers.rs` (meandering channels from the zero band of a warped low-frequency field — U-profile beds, fading out in mountains, meeting the sea at grade), `lakes.rs` (sparse thresholded footprints in flat eroded inland country — min-carved bowls under a locally flat quantized level; lake beats river per column, rivers keep a buffer, terraced country excludes lakes), `caves.rs` (carve where two independent 3D-noise bands intersect, land columns only), and `classify.rs` (per-column `SurfaceKind` — Ocean/Beach/Plains/Mountain/Snow/River plus the climate biomes Forest/Taiga/Savanna/Marsh/GravelShore — with each kind's block rules, tree density, and tree species as `SurfaceProps` table data; broad temperature and vegetation fields in `terrain.rs` shift the stone/snow lines and pick the biome, never the terrain). `SEA_LEVEL = 128` of a 256-block world. Structures run as a decoration pass (fill → carve → decorate) using pure apron evaluation: candidates come from per-family salted position hashes (`structures_near` — ordinary trees with density and species from the surface's `SurfaceProps` row and five hash-jittered silhouettes; rare 2×2-trunk landmark trees on a coarse 64-cell grid; boulders on rock; bushes on grass), trunk roots replace the surface cell — the single exception to decoration's write-into-Air-only rule — and every chunk within `STRUCTURE_APRON` computes the identical structure independently, so structures span chunk borders with no pipeline state. Sky chunks resolve to the shared `AIR_CHUNK` sentinel Arc (never meshed, recognized by pointer).

### Chunk pipeline (core/pipeline.rs + mesher.rs)

A worker pool replaces the Java one-item-per-frame loop. The main thread owns the chunk store and scheduling; workers run pure functions (terrain gen, meshing) over immutable snapshots — a mesh job gets a padded 18³ copy of its chunk (a one-block shell from all 26 neighbors, feeding per-vertex AO and water corner heights), no shared mutation. Staleness is handled by generation counters: results whose `gen` doesn't match the slot's current counter are dropped. A newly generated chunk bumps its own and its Ready neighbors' counters — face neighbors unconditionally, diagonals only where the shared shell cells can matter. Block edits go through `Pipeline::set_block` (dig/place): copy-on-write via `Arc::make_mut`, bumping the chunk and only the neighbors whose shell contains the edit. Vertices are packed as two u32 words — word 0 geometry at half-block resolution, word 1 material with a 10-bit texture-layer field (`MAX_TEX_LAYERS` = 1024) and, for water, the surface/flow payload in the upper bits.

### Lifecycle robustness

The suspend/resume and device-loss paths are standing regression targets for a future Android port. `Renderer::new` is a pure constructor so device-loss recovery is "build a new one and re-upload meshes" (`Game::rebuild_gpu_resources`). `Game::on_suspend` must be cheap and synchronous — on iOS/Android the process may be killed with no further callbacks. Test via `just run --drill` (automated) or F9/F10 at runtime; F8 takes a screenshot.

## iOS notes

`apps/ios/xcode/DigBlock.xcodeproj` is generated from `project.yml` — edit the yml and rerun `xcodegen`, never edit the project file directly. Simulator/device builds need full Xcode (Command Line Tools alone are not enough); `just check-ios` is the fast compile gate that needs no Xcode.
